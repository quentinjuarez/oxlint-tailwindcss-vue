# oxlint-tailwindcss-vue 0.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A CLI that checks the Tailwind CSS classes of Vue SFC templates with the user's own oxlint and oxlint-tailwindcss, and reports each finding at its exact line and column in the `.vue` file.

**Architecture:** Each `.vue` file becomes an offset-preserving virtual `.ts` file where every class attribute is a `__(...)` call at its original offset. One oxlint run per config group lints the virtual files with a derived config that keeps only the Tailwind rules; byte offsets come back through UTF-16 indices to the original file. A thin CLI wraps the `lint()` API.

**Tech Stack:** TypeScript 5.9 (ESM, NodeNext), Node 22.12+, `@vue/compiler-sfc` 3.5, `@babel/parser` 7, Vitest 5 with fast-check, oxlint 1.94 and oxlint-tailwindcss 1.17.2 as peers.

**Spec:** `docs/design.md` (approved 2026-11-20). The contract details live in `.claude/skills/virtual-file-contract/SKILL.md`; every task that touches the virtual file reads it first.

## Global Constraints

- Node `>=22.12.0`, ESM only, `tsconfig.json` as committed (`noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`, `verbatimModuleSyntax`). Import local files with the `.js` extension.
- Runtime dependencies: only `@vue/compiler-sfc` and `@babel/parser`. Everything else comes from `node:` built-ins (`util.parseArgs`, `util.styleText`, `child_process.spawn`, `module.createRequire`). Adding a runtime dependency needs Quentin's approval.
- oxlint `>=1.94.0` and oxlint-tailwindcss `>=1.17.2`, resolved from the user's project, never bundled.
- Private callee: `__`. Skip codes exactly as in the skill: `entity`, `invalid-expression`, `invalid-escape`, `quote-in-unquoted-value`, `no-room`, `template-wrapper`, `template-lang`, `template-src`, `parse-safety-net`, `sfc-parse-error`. Notice code: `unquoted-key`.
- Exit codes: 0, 1, 2, 130, 143 with the meanings of the design's "Exit codes" table.
- Output formats `default`, `json`, `github`; columns in UTF-16 units for `default` and `github`, UTF-8 bytes for `json`.
- English everywhere; no em dashes, no `--` as punctuation, no ellipses, no emojis, no curly quotes. No comment that restates the code.
- Every heavy command goes through the RAM lock, one at a time: `export PATH="$HOME/.nvm/versions/node/v26.13.1/bin:$PATH"` then `~/.claude/bin/heavy-lock yarn test <files>` (or `yarn verify`). Never run two at once.
- `test/fixtures/` is byte-exact and ignored by oxlint and oxfmt. CRLF fixtures live under `test/fixtures/crlf/` (stored with `-text`).
- Each task ends with `yarn verify` green, one Conventional Commit on `main` (no trailers), and `git push`.

## Review Focus

1. A `.vue` file saved with CRLF line endings: every reported line and column is exact in all three formats. Test: Task 10, `reports exact positions in a CRLF component`.
2. French or emoji text before a class on the same line: the `default` column counts UTF-16 units and the `json` column counts bytes. Test: Task 10, `reports UTF-16 columns and byte offsets after non-ASCII text`.
3. A monorepo package run from a subfolder, with `.oxlintrc.json` higher up and a relative `entryPoint`: findings still appear. Test: Task 10, `finds the config above the cwd and resolves a relative entryPoint`.
4. Paths that match no `.vue` file, or that do not exist: the first exits 0 with a short notice, the second exits 2 with the path named. Test: Task 12, `exits 0 when no .vue file matches` and `exits 2 on a missing path`.
5. A project where oxlint-tailwindcss is not in `jsPlugins`, or the CSS entry point is missing: exit 2 with a message that says what to add. Test: Task 9, `refuses a config without oxlint-tailwindcss` and `refuses a missing entry point`, then Task 12, `exits 2 with the preflight message`.
